# IBM Bob Usage Statement

## How We Used IBM Bob

### Plan Mode — Architecture and Specification Review

IBM Bob's Plan mode was used to review the TraceForge AI architecture before implementation. We described the ContractGuard investigation workflow and asked Bob to identify unnecessary complexity, validate the state machine design, and suggest simpler implementations where the spec could be fulfilled with less code.

Bob also helped review the OpenAPI specification structure for UploadLab to confirm that the documented contract clearly described the intended multipart field name and multi-file behavior.

### Agent Mode — Investigation Task

The core demonstration of ContractGuard requires IBM Bob to perform a genuine investigation of the UploadLab broken fixture. The investigation prompt (generated by ContractGuard at `/api/v1/investigations/:id/bob/investigation-prompt`) instructs Bob to:

1. Read the OpenAPI specification and documentation in the workspace
2. Read the frontend API client source code
3. Read the Rust Axum upload handler
4. Examine the existing test suite
5. Identify differences between documented behavior and implementation

Bob's investigation is performed in Agent mode, reading actual source files in the isolated workspace created by ContractGuard.

### Subagents — Parallel Investigation

The investigation prompt requests three focused parallel investigations using Bob's Explore subagents:

- **Subagent A (Frontend):** Inspects the React upload component and API client, identifying the wrong multipart field name
- **Subagent B (Backend):** Inspects the Rust handler, identifying single-file processing
- **Subagent C (Contract):** Reads the OpenAPI spec and acceptance criteria, identifying test gaps

Bob synthesizes the subagent findings, eliminates duplicates, and prepares the `diagnosis.json` artifact with verified source references.

### Document Understanding

Bob reads and understands the project documentation before investigating code:
- `openapi.yaml` — the authoritative API contract
- `docs/upload_api.md` — detailed API documentation
- `docs/acceptance_criteria.md` — acceptance criteria
- `docs/architecture.md` — system architecture

### Implementation Assistance

After the developer approves the fix plan in ContractGuard, Bob's implementation prompt instructs it to:
- Read the approved diagnosis artifacts
- Implement minimal corrections for BUG-001 and BUG-002
- Add regression tests
- Run `cargo test` and capture results

### Regression Test Generation

Bob adds tests to the UploadLab test suite that verify multi-file processing and correct field name behavior. These tests are run independently by ContractGuard's verification engine to confirm the fix.

### Code Review

Bob produces a `review.md` artifact covering correctness, test coverage, security implications, unrelated changes, and remaining risks. The ContractGuard verification engine independently validates this by running the actual tests — Bob's self-assessment does not determine the verified status.

## Technologies Used

- IBM Bob 2.0 IDE (Plan mode and Agent mode)
- Bob Explore subagents for parallel investigation
- Bob's document understanding capability
- Structured artifact handoff via local workspace files
